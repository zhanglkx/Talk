## 一、用户故事与信息边界

用户以虚构问题询问某月收支、分类支出、两月比较或最近记录；答案含明确月份/时区、金额、记录数和可追溯来源。

提问文本本身会发送模型供应商，页面警示不能输入真实敏感信息；不传查询结果并不代表问句绝不会外发。账本备注、分类列表、完整账单不发模型。

模型只帮助识别意图和提出工具计划；服务端决定权限、参数、金额和事实模板。既有账本在AI故障时必须继续工作。

## 二、允许与禁止

| 能力 | 规则 |
|---|---|
| 允许意图 | monthly_summary、category_summary、month_compare、recent_entries、needs_clarification、unsupported。 |
| 只读工具 | getMonthlySummary(month)、getCategoryBreakdown(month,direction)、listEntries(start,end,categoryId?,limit≤20)。 |
| 拒绝能力 | 新增/编辑/删除流水、任意SQL、任意URL、他人数据、模型传userId、付款/理财建议、无限工具循环。 |
| 单次限制 | 最多2个明确自然月、3个只读工具、20条明细；模型仅一次规划，最多一次受限重试；总deadline不可因重试延长。 |

## 四、配置与成功门

模型ID、供应商、并发/每日费用上限、token和deadline都是实施前显式配置，不在文件内填假价格或假预算；没有可用预算不触发真实调用。

本阶段允许可替换ModelAdapter做离线权限/故障测试，但要标注离线；真实模型表现必须由M7验证，不能把固定mock回答当作AI产品已上线。

至少能在授权虚构数据上完成一个真实模型规划→工具→模板答案；所有安全回归通过，工具计划及费用可追踪。真实模型访问阻塞则M6在线部分未完成。
