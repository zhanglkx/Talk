## 一、架构与信任边界

AiController → AiService（冻结身份/asOf、预算预留）→ ModelAdapter（只看问句+工具Schema+时区+asOf）→ PlanValidator → ToolGateway → 本人只读领域服务 → FactBuilder/AnswerRenderer → 响应。

AiModule不注入底层Repository或DB访问给模型；ToolGateway使用受控事务manager调用Reports/Entries只读服务。账本数据是事实，不是下一轮系统指令；工具结果绝不回灌模型。

规划、预算和失败记录为独立步骤；模型网络等待期间没有打开数据库事务。规划完成后才创建短只读快照事务。

## 二、结构化计划Schema

建议内部计划：kind、months（最多2个YYYY-MM）、direction?、categoryCandidate?、tools（严格判别联合，最多3条）。Schema拒绝未知字段，明确禁止userId/sql/url；不同kind校验对应工具组合。

asOf在请求开始固定；本月/上月按Asia/Shanghai计算；年份范围/起止/未来月份规则沿用业务Schema。相对时间工具参数不得各取自己的now。

类别候选在服务器按本人分类解析；无匹配或多ID同名返回澄清，不能泄露别人的匹配候选。分类名称只视为数据，Web正常转义。

校验失败最多一次受限重试，供应商失败同样至多一次；两者共用总尝试上限2，总deadline不可重置。无无限Agent循环。

## 三、只读执行与事实渲染

执行最多3个工具，使用同一个READ ONLY、REPEATABLE READ事务manager；锁/statement/请求总时间有上限，结束即释放。任何工具不能退回全局Repository破坏快照。

单次最多2个月/20条明细；listEntries排除备注，只返回必要字段。用户ID由会话注入，工具公开Schema无此参数。

FactBuilder使用string/BigInt计算收入、支出、净额、差额；百分比采用显式舍入精度并带口径，前月0只给绝对差。不能直接输出模型数字。

P1回答由确定性模板生成，不再额外请求模型润色；evidence包含月份、时区、categoryId/归档标记、entryCount、查询口径，不暴露SQL/凭据。

## 四、运行表、配额与超时

新增migration：ai_runs(id,user_id,request_id,model_id,status,工具名,token,费用,耗时,错误码,created_at)；ai_usage_daily(user_id,上海day,预留/已结算次数与费用)。不存问句/完整答复/账本。

发起网络前在短事务中原子检查并预留每日次数/费用；超限429。响应后另一次短事务结算。未知计费保留reservation待核对，不把未知计成0。

费用使用精确十进制或最小计费单位，记录供应商价格版本/日期；不能用任意hard-coded价格假算“成本已控制”。进程中断的reservation需有受控核对状态，不直接到期清零。

首次真实调用前必须配置保守总deadline与token上限；小样本测量后再调整，禁止首次调用无上限。p95<12s为目标不是默认事实。Abort/cancel、重试次数、DB快照timeout应在统一时间预算内。

单实例AI并发限额与按用户限流；密钥/预算配置缺失拒绝启用AI，普通账本仍可运行；不声称多副本全局控制。

## 五、前端、契约与测试

生成AI request/response OpenAPI类型；Web question≤500提示仅虚构问题；事实卡片来自facts而非parse answer。HTTP200结构化响应的status明确区分answered、needs_clarification与unsupported；后两者facts为空，不渲染数值卡片。非法计划两次仍失败用稳定错误码/503而非伪答；供应商503仍提供月报跳转。

离线可替换ModelAdapter验证畸形JSON、额外工具字段、恶意类别、不同用户、取消、超预算、0基数。真实DB验证snapshot/配额并发/无业务表写入。

HTTP带真实会话+CSRF；普通账本接口在供应商不可达时仍成功。日志用结构化元数据，不写请求body或SDK错误中潜藏密钥/问句。
