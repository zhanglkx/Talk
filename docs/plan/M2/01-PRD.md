## 一、用户故事与范围

作为登录用户，我能建立收入/支出分类，将一笔虚构 CNY 收支记入自己的分类，并按月份/方向/分类查看记录。

必做：分类创建/列表/改名/归档、流水创建/分页、金额/日期校验、对象权限、Web分类页/新增页/列表页。流水编辑/删除、月报在M3，不做预算、导入、多币种或图表。

分类名在同一用户和方向下忽略大小写后不重复；trim后1～30字符，方向income/expense创建后不可改变。已归档分类不出现在新增选择器，历史显示仍可读。

## 二、功能验收编号

| 编号 | 产品行为 |
|---|---|
| M2-R01 | 本人能创建分类；同方向有效重名409；A/B可各有同名分类。 |
| M2-R02 | 改名更新历史展示名称；归档不可逆（本期无恢复），不删除历史流水；归档后可新建同名不同ID分类。 |
| M2-R03 | 创建流水金额严格正整数分字符串，单笔≤999999999分；仅CNY；发生时间带时区；备注最多200字符。 |
| M2-R04 | 分类必须属于本人、方向匹配且未归档；他人分类404，归档/方向冲突409。 |
| M2-R05 | 创建必带UUID Idempotency-Key；同用户同键同规范体返回首次201，不同体409；所有相关记录同事务写入。 |
| M2-R06 | month为YYYY-MM；默认20/页，最大100；列表只含本人未删流水，排序稳定。 |
| M2-R07 | Web支持加载、空态、字段错误、服务错误、重试；请求重试沿用同一键，不以按钮disabled代替服务幂等。 |

## 三、阶段接口

| 接口 | 契约 |
|---|---|
| GET/POST /api/v1/categories | 列表可按direction过滤；默认返回活动分类，includeArchived=true用于历史；POST{name,direction}→201。 |
| PATCH /api/v1/categories/{id} | 仅{name}或{archived:true}；UUID校验；方向字段拒绝；修改200；归档重复提交保持200。 |
| POST /api/v1/entries | {direction,categoryId,amountMinor,currency,occurredAt,note?} + Idempotency-Key →201及Location。 |
| GET /api/v1/entries | month必需，direction/categoryId可选，page/pageSize；返回items/page/pageSize/total。offset最多10000，超出400。 |

## 四、数据与交互口径

amountMinor使用规范十进制字符串（如32050），不接受0、负数、小数、指数、空白、前导零。Web的“320.50元”按字符串拆分转32050分，不能浮点乘100。

occurredAt由客户端提交带偏移ISO时间，服务端规范化UTC；月份按Asia/Shanghai的半开边界筛选。列表与后续月报共用时间函数。

列表错误可重试；新增未知结果时保留原请求体/键并提示“结果待确认，可重试”，参数变化后才创建新操作键。401清用户缓存，换账号不得显示上一个账号数据。

分类改名影响历史名称展示，金额不变；归档后同名分类按ID分开展示并标记归档。本阶段定义该规则供M3报表沿用，尚非已实现声明。

## 五、退出门槛

A/B账号分类和流水互不可见；数据库复合外键拒绝跨用户引用；缺认证401、对象非本人404、非法参数400和冲突409都有HTTP/真实DB测试。

创建至少覆盖重复/冲突键、参数化SQL、事务回滚；若基础幂等未完工，POST创建保持未发布，不以“后续M3补齐”当作M2可用验收。

360px与桌面均能键盘操作分类→创建→列表；API契约重新生成，Web不导入Entity；示例仅虚构数据。
