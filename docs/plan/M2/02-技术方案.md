## 一、架构与目录

新增 src/modules/categories/{category.entity,categories.module,controller,service,repository,schemas}.ts 和 entries/{entry.entity,idempotency-request.entity,entries.module,controller,service,repository,schemas}.ts（路径为目标规划）。

Guard注入会话身份；Service负责规则、规范化与事务；Repository封装绑定参数查询并接收事务manager；数据库保护最后一道约束。Controller不写SQL，Web不承担授权。

M1共同的ConnectionLifecycle、Auth/Origin/CSRF、requestId/Filter继续复用；不新建第二个DataSource。

## 二、Entity与migration

| 对象 | 关键约束/索引 |
|---|---|
| categories | UUID PK；user_id FK；direction CHECK；name与archived_at；UNIQUE(user_id,id)；部分唯一索引(user_id,direction,lower(name)) WHERE archived_at IS NULL。 |
| entries | UUID PK；user_id/category_id复合FK；direction CHECK；amount_minor BIGINT CHECK 0<值≤999999999；currency CHECK CNY；occurred_at timestamptz；note≤200；client_request_id UUID；deleted_at；UNIQUE(user_id,client_request_id)。 |
| idempotency_requests | (user_id,key) PK；request_hash；entry_id；首次响应status/location/body JSONB；created_at。流水与首次快照同事务保存，不自动过期/复用键。 |
| 列表索引 | (user_id,occurred_at DESC,id DESC) WHERE deleted_at IS NULL；避免无性能依据地为所有字段加索引。 |

## 三、创建事务与分类竞态

先校验/规范化请求，生成固定字段序列的指纹（UTC时间、标准金额、明确note缺省），不hash原始JSON。规则从M2写入公共函数，M3继续强化重放而非换语义。

READ COMMITTED事务使用manager：INSERT幂等行 ON CONFLICT DO NOTHING RETURNING。若冲突，SELECT该用户键 FOR UPDATE读取并比较；不同409，相同重放首次201/Location/body。DO NOTHING避免捕获唯一异常后继续使用aborted事务。

新键分支锁分类行，检查userId/方向/archived_at；写流水与快照，提交成功才返回。分类归档也锁同一行，按先提交者确定有效性。任何失败回滚两表。

事务内从manager.getRepository获取Repository；不调用全局Repository。手工QueryRunner在finally release。避免在事务中做模型调用或等待浏览器。

## 四、查询、前端状态与错误

列表SQL先约束user_id、deleted_at IS NULL、UTC半开边界；过滤输入使用绑定参数；排序occurred_at DESC,id DESC。total/items需同一只读快照或明确单SQL返回，避免并发时分页信息明显不一致。

API金额与Entity保持string；不能使用全局BIGINT→Number parser。日期格式运行时校验真实日期，不仅字符串正则；月份合法性与年份范围建议2000～2100写入Schema。

Web引入一套路由与一套服务器查询缓存即可；查询键包含当前用户身份、月份与筛选。表单局部state；提交成功失效相关分类/流水缓存；401/logout/用户切换清缓存。

403防伪、404他人对象、409重复分类/幂等冲突、503依赖问题映射为友好状态；不记录备注、密码、Cookie或完整body。错误fields指向表单项。
