## 一、阶段目标与用户

用户为本人和受控演示者，仅使用虚构身份及数据。本阶段要解决“从空库建立账号、证明登录身份、拒绝未授权请求”三个问题；不是公开注册或支付系统。

核心故事：作为学习者，我能先运行 migration/seed，再登录查看自己的身份；退出后旧 Cookie 不再有效；刷新页面能够恢复有效会话，失效会话跳回登录。

完成标准不以页面出现登录按钮为准，而以 PostgreSQL 持久化、会话轮换、跨账号测试、CSRF 和可复现命令为准。

## 二、必做与非目标

必做：users/sessions migration、User Entity/Repository、受控 seed、登录/退出/me、AuthGuard、Origin/CSRF、请求 ID/基础错误映射、最小 Web 登录态。

最小业务路径选择 GET /auth/me：以会话中的 userId 查询 UserRepository，返回本人身份；该链路即 Controller → Service → Repository → PostgreSQL 的垂直切片。

可选：时间有余且认证验收通过后增加本人分类创建/列表。不能为了演示第一笔流水省略后续金额、事务和幂等要求。

不做：公开注册、密码找回、邮件验证码、JWT 双令牌、第三方登录、完整分类/流水、月报、AI、Redis、Docker。

## 三、需求与验收编号

| 编号 | 行为与验收 |
|---|---|
| M1-R01 | 空库显式执行 migration 后具备 users/sessions；再次执行不重复建表；应用启动不自动建表或迁移。 |
| M1-R02 | seed 建立两个虚构账号；只保存密码哈希，不把密码写入代码、文档或日志；再次执行不悄悄重置已有密码。 |
| M1-R03 | 正确凭据登录成功并轮换 Session ID；错误用户名和错误密码均返回相同 401 文案，不泄露账号存在性。 |
| M1-R04 | me 从会话取得身份；未登录、已退出、闲置/绝对过期均 401；客户端 userId 不改变返回用户。 |
| M1-R05 | 退出销毁服务端会话并清同名/同路径 Cookie；重放旧 Cookie 不恢复登录。 |
| M1-R06 | 登录检查可信 Origin；已登录写请求检查 Origin 和 X-CSRF-Token。缺失或错误返回 403。 |
| M1-R07 | Web 显示加载、账号、登录失败、网络失败和退出状态；密码及会话不得存入 localStorage。 |
| M1-R08 | 数据库离线时 health 仍为 200、ready 为 503、依赖数据库业务安全返回 503；恢复后业务能重试。 |

## 四、接口产品契约

| 接口 | 输入与成功行为 | 主要失败 |
|---|---|---|
| POST /api/v1/auth/login | username/password；200 返回最小 user，设置 HttpOnly Cookie；先校验 Origin。 | 400 参数非法；401 凭据错误；403 Origin；429 限流；503 数据库。 |
| GET /api/v1/auth/me | Cookie；200 返回 user{id,username} 和 csrfToken；响应不缓存。 | 401 未登录/过期；503 数据库。 |
| POST /api/v1/auth/logout | Cookie、Origin、X-CSRF-Token；204，无响应体；前端清状态。 | 401 无效会话；403 防伪失败；503 销毁失败。 |

## 五、输入、会话与交互规则

本阶段建议契约：用户名规范化为 trim 后的小写 ASCII，3～32 个字符，仅 a-z、0-9、下划线；seed 和登录采用同一规则。密码原样验证，不 trim；长度 12～128。此为阶段设计，实施时要写入 Schema 与测试。

账号由本地受控命令建立，密码通过安全交互输入或一次性向操作者展示；种子不把秘密落盘。重复运行只补缺失演示账号，冲突给明确反馈。

会话闲置 12 小时、绝对 7 天；到达任一截止点即失效。用户切换必须生成新会话并重置缓存，不能短暂显示上一用户内容。

登录页：字段标签、键盘操作、提交期间禁重复提交；统一“用户名或密码错误”；503 显示服务不可用，不误报密码错误。

me 返回 CSRF token 后存于页面内存；401 清理身份并回登录；网络失败与401区分。所有用户响应只包含公开字段。

## 六、阶段交付与出门条件

提供 migration/seed/启动顺序和测试库保护说明；提交 Entity、迁移、接口 Schema、Swagger 响应描述及生成类型。文档要求是未来交付，不表示这些已实现。

用两个独立 Cookie jar 演示登录、me、退出、旧 Cookie 拒绝；同一浏览器换账号后不保留前一账号状态。

空库迁移、重复迁移、哈希种子、数据库离线/恢复、Cookie 属性、轮换/过期、CSRF、错误契约和前端身份状态均有测试证据。

任一鉴权/会话安全测试失败，不进入 M2；可推迟分类小样，不能用 hard-coded userId 或内存会话假装完成。
