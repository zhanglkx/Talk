## 三、数据库设计

| 对象 | 字段与约束 |
|---|---|
| users | id UUID PK；username VARCHAR(32) UNIQUE（已规范化）；password_hash TEXT NOT NULL；created_at timestamptz NOT NULL。UUID 可由 Node crypto 生成，避免无必要扩展。 |
| sessions | session_key_hash CHAR(64) PK；user_id UUID FK users；created_at、last_seen_at、idle_expires_at、absolute_expires_at timestamptz；必要 CSRF/会话状态 JSONB；到期索引。 |
| migration 历史 | 由 TypeORM 管理已执行版本；手写/生成 migration 均需审查 SQL。已执行 migration 不就地修改；增加新版本前向演进。 |

## 四、迁移、种子与测试库保护

CLI 从与应用相同的 DATABASE_URL 配置键读取值；不同进程可注入不同本地数据库 URL，不新增平行 host/password/TEST_DATABASE_URL 体系。

迁移采用 TypeORM MigrationInterface up/down，生成命令可能需要临时 introspection 数据源，但绝不打开 synchronize。CLI 在脚本 finally 中 destroy DataSource。

测试使用独立、确认可清理的本机数据库；运行 destructive reset 前验证数据库名为专用测试库并要求显式允许；拒绝默认 postgres 库、开发库或不受控远程地址。

seed 不使用固定演示密码；使用 Argon2id 异步哈希。测试固定凭据只在隔离虚构 fixture 内、不可拿来当运行账号。现有账号再次 seed 不重置密码。

先创建 users，再 sessions；down 反向删除仅在可丢弃测试库演练。down 不能充当生产数据恢复，任何含数据库重置的流程都写清目标。

## 五、会话 Store 与 Cookie

采用维护中的 express-session；持久化 Store 适配层复用项目 DataSource。选用现成 PostgreSQL Store 时先核对字段/摘要键、过期与 touch 行为；不符合要求则以清晰、可测试的薄适配实现 Store 接口，不再自建 Cookie 加密/签名协议。

Store 的 get/set/destroy/touch 全部以 SHA-256(Session ID) 为 DB 键；明文 SID 仅存在 Cookie/受控内存，不写 DB/日志。会话最少持有 userId、csrfToken、创建/截止时刻，不保存账本或密码。

set 写入已认证会话；saveUninitialized:false 不保存匿名预登录会话。touch 仅延长闲置期限，不越过 absolute_expires_at；读写均检查最早截止点。

登录通过密码校验后 regenerate、设置 userId/随机 CSRF token 与时间、显式 save 成功才 200。失败不可发出看似有效登录 Cookie。退出 destroy 成功才清 Cookie/204，销毁失败返回可重试的503。

本地 loopback HTTP 可使用 ledger.sid、Secure:false；HTTPS 部署使用 __Host-ledger.sid、Secure:true、HttpOnly:true、SameSite:Lax、Path:/、无 Domain。仅信任受控代理，禁止公网 HTTP 关闭 Secure。

SESSION_SECRET 是服务端配置，缺失拒绝认证配置启动；不能写死或从 DATABASE_URL 派生。数据库仍只有一个 DATABASE_URL；会话密钥与可信 Origin 属不同用途的配置。

## 六、认证、防伪、限流与错误

登录先检查可信 Origin，再 Schema/限流/密码；用户名不存在也做等价的哈希验证路径以减少明显差异。Argon2id 参数按维护库推荐与本机耗时测量选择，不在文档中编造已测参数。

AuthGuard 只从有效 session 取得 userId。me 查询该 ID，用户不存在视为无效会话；不接受 body/query 的 userId 或客户端 Header 作身份。

Origin 使用 URL parser 解析后比对配置的 origin（scheme/host/port），不是 startsWith/includes。浏览器状态修改请求缺 Origin 拒绝；GET me 不要求 CSRF。登录后写请求须匹配会话随机 X-CSRF-Token，比较长度一致后常量时间比较。

登录限流按 IP + 规范化账号设置两级有界窗口；建议学习环境阈值分别 30/5 次每5分钟，作为可配置设计值，实际测量可调整。IP 只从可信代理链获取；单实例内存限流不声称分布式全局限流。

统一失败 JSON：error{code,message,requestId,fields?}；400 校验、401 未登录/凭据、403 防伪、429 频率、503 依赖不可用、500 未知错误。响应不含密码、hash、SID、URL或堆栈。me/login 使用 Cache-Control:no-store。

## 七、前端与公开契约

Web API 模块只导入 generated/api-types.ts 的 paths/响应类型；不导入后端 Entity。使用同源 fetch，Cookie 凭据随同源请求，状态修改带 Origin 浏览器自动头和内存 CSRF token。

页面启动调用 me，401 显示登录；网络失败显示服务错误而非跳转循环。登录成功调用 me 初始化身份/CSRF；退出成功清身份及后续查询缓存。

输入 Schema、显式响应描述与 HTTP 测试共同核对 OpenAPI。Zod Standard Schema 与当前 Nest/Swagger 锁定版本的集成先做小测试再接入，不能只写类型断言就声称运行时校验。
