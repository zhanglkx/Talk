## 执行容量与日期口径

每周4小时模式：3小时深度任务＋0.5小时阅读＋0.5小时算法/复盘；5小时模式：4小时深度任务＋1小时轻量学习。任务卡约15～16小时属于核心工作估算，另保留四周共4小时轻量学习后，总量约19～20小时。四周5小时模式才基本容纳全部内容且缓冲很少；4小时模式通常需至少5～6周。环境阻塞/缺陷超过余量即顺延，不增加通勤硬编码或熬夜补课。

日期为七个四周学习月的目标窗口；依赖阶段未验收则顺延。绿周≥5小时、黄周3～4小时、红周≤2小时只维护与复盘；睡眠、权限、事务和测试不用于“赶日期”。

## 一、进入阶段前的准备

只做文档中列出的 M1，不改产品范围；确认本机真实 PostgreSQL、项目锁定 Node/pnpm 能运行。已知总计划是 4～5 小时/周，不把通勤记为编码容量。

现有命令（仓库根）：pnpm check 依次跑 contracts、typecheck、根 pnpm test 和 build，其中根 pnpm test 自 M1-S12 起先跑 API 单元/HTTP 测试、再跑 Web。真实库测试是单独的 test:db（M1-S10 建立，只连 ledger_it），不在 check 中。本次文档编写没有重新运行业务验收。

未来需实现的脚本名建议：db:migrate、db:status、db:seed、test:integration。它们当前不存在；先在 package scripts实现并验证，再在运行说明引用。

## 四、容量、停损与可选任务

上表核心任务估算15小时，不含环境阻塞和陌生库研究；四周投入16～20小时不是硬期限。16小时模式余1小时，20小时模式最多留5小时用于阅读/回归/缓冲，不把全部余量填成功能。

工作日总计两次15分钟用于文档/复盘；每周算法或复盘30分钟。周末两个1.5小时深度块加上述1小时构成4小时基础；状态好时额外1小时只补测或研究。

卡片超过两小时停止扩展，保留失败输出和下一步；下次从同一点继续。Store/初始化阻塞优先解决，不以MemoryStore、硬编码身份、关CSRF或删除测试绕过。

可选分类小样移到M2也不影响M1认证门；若认证未通过则整个阶段顺延，后续日期只是目标窗口。
