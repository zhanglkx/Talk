### M7-S01 详情

- 来源：任务卡 M7-T01 的前半。30 道题与期望答案（T01 后半）在本步通过后再展开。
- 计划：评测前先固定“考场”：同一份虚构数据、同一个“当前时间”（asOf）、同一个版本号。其中任何一项变了，两次评测的分数就无法比较。
- 动作：
  1. 按技术方案的参考 fixture 固化数据：A/B 两名虚构用户、使用稳定 UUID 的分类、共 10 条物理流水（含已软删记录和 B 的记录）。
  2. asOf 固定为 `2027-03-15T04:00:00Z`（上海 12:00），只能由测试依赖注入。
  3. 计算 fixture 内容 hash，连同 migration 版本、应用 revision 一起记录。
  4. 写对账检查：加载到专用评测库后核对条数。
- 注意事项：
  - 只用专用本机评测库，不重置开发库；数据全部虚构。
  - fixture 冻结后若要改动，必须换版本号并重算 hash，不能悄悄改。
  - 本步不写题目、不调用模型。
- 验收：
  1. 空评测库加载 fixture 后对账通过：物理流水 10 条，A 有效流水 8 条，A 的 2026-12 和 2027-03 无记录。
  2. 重复加载 hash 不变；改动任意一条数据，hash 改变。
  3. 记录中有 fixture 版本、hash、migration 版本和应用 revision。
