# 个人账本全栈学习计划

2026-10-12 至 2027-04-25｜7 个四周学习月｜每周 4 小时保底、5 小时上限

适用项目：ledger-workspace　版本：v1.0　制定日期：2026-10-09

## 一、计划目标

在 28 周内完成一个仅使用虚构数据的个人账本学习项目：React Web → NestJS API → PostgreSQL/TypeORM → 测试与交付 → 受限只读 AI。目标不是堆叠技术名词，而是能够独立解释并验证一次完整请求在前端、认证、业务服务、数据库、测试和 AI 边界中的行为。

本计划从当前已有的 NestJS、React、TypeORM 与 PostgreSQL 基础开始。第一阶段直接进入版本化 migration、用户认证和第一个业务垂直切片。

## 二、每周学习节奏

| 时间块 | 时长 | 安排 |
|---|---|---|
| 周末深度块 A | 2 小时 | 完成一个最小垂直切片：先写失败测试或契约示例，再做最小实现。 |
| 周末深度块 B | 1.5～2 小时 | 完成调试、真实 PostgreSQL 测试、OpenAPI 类型生成、复盘与提交。 |
| 工作日轻量块 | 每周 1～2 次，每次 20～25 分钟 | 只做低认知事项：阅读官方文档、追踪一次请求链路、整理下个深度块任务或复盘一题算法；不安排硬性交付。 |
| 算法 | 每周 30～45 分钟 | 一题或半题即可；记录输入边界、复杂度、失败思路和替代解法。连续加班时允许暂停。 |
| 月末回顾 | 30 分钟 | 演示本月成果，更新实际投入、完成证据、阻塞项与下一月唯一调整。 |

通勤时间不作为必需编码时间。通勤可选用于听课、阅读或复盘；涉及建模、编码、调试、迁移和测试的任务固定放在周末深度块。

## 三、容量与节奏规则

- 绿色周（≥5 小时）：完成本周必做项后，再做一个小型可选项。
- 黄色周（3～4 小时）：只做必做项，不新增功能范围。
- 红色周（≤2 小时）：只运行检查、修一个小问题或写下一步说明；不开始新功能，也不在下一周熬夜补回。
- 每个学习月的退出门槛未通过时，延续当前学习月；不得并行开启后续主题。
- 七个四周窗口按每周 5 小时排；4 小时的周较多时，一个阶段通常要 5～6 周，日期顺延，质量门不降低。

## 五、各学习月的行动清单

### M1｜业务数据库与认证最小闭环

2026-10-12 ～ 2026-11-08

学习重点：学习 TypeORM Entity、Repository、Migration、DataSource、QueryRunner，以及 PostgreSQL 约束和事务基础。

必做事项：

- 实现显式 migration 命令和虚构用户 seed；应用启动不得自动改表。
- 建立 User/Session 的最小数据模型与 AuthModule：登录、退出、GET /auth/me。
- 密码使用成熟的异步哈希方案；无公开注册；所有密钥只在服务端环境变量中存在。
- 首个受认证保护的业务路径是 GET /auth/me：用会话里的 userId 查询本人，走通 Controller → Service → Repository → PostgreSQL。分类小样只在认证验收通过且有余量时做；流水留到 M2，因为创建流水从第一个公开接口起就必须带幂等。
- Web 只做登录、当前身份和错误态，不做复杂视觉设计。

退出门槛：空数据库能完成 migration → seed → 启动 → 登录；A/B 两个会话互不串号（各自的 me 只返回本人）；认证与真实 PostgreSQL 集成测试通过；OpenAPI 与 Web 类型同步。

### M2｜分类、流水创建与列表

2026-11-09 ～ 2026-12-06

学习重点：学习 Nest Guard/Pipe/Filter、服务层逐对象授权、Zod 输入校验和金额字符串的端到端处理。

必做事项：

- 实现分类创建、列表、改名和归档；归档分类不可再用于新增流水。
- 实现流水创建和列表分页：创建必带 Idempotency-Key，流水与幂等记录同事务写入；查询始终按当前会话 userId 约束。
- 完成分类页、流水列表页和创建表单；优先空态、字段错误和移动端可用性。
- 每个接口先补 HTTP/数据库测试，再生成 OpenAPI 与 Web 类型。

退出门槛：登录后能创建分类和流水并在列表中查看；同键同请求只产生一笔流水，同键不同请求体返回 409；非法金额、非法日期、跨用户分类和归档分类均被拒绝。

### M3｜流水生命周期、月报与幂等重放

2026-12-07 ～ 2027-01-03

学习重点：学习 SQL 聚合、GROUP BY、SUM、上海时区月边界、软删除和 TypeORM 事务。

必做事项：

- 实现流水编辑、软删除和筛选；流水被编辑或软删后，同键重放仍返回首次 201 响应，不新建流水。
- 实现月报：收入、支出、净额、分类分布、无记录状态；金额全程不转为 JavaScript Number。
- 完成月报页面、月份筛选、空态和接口失败态。
- 实现并演示主流程：登录 → 分类 → 新增 → 月报 → 编辑/删除 → 退出。

退出门槛：编辑或软删后同键重放仍返回首次响应、不新建流水；月报可用独立 SQL 对账，分类之和与总额一致。

### M4｜P0 质量门、事务与并发可靠性

2027-01-04 ～ 2027-01-31

学习重点：将功能收敛为可信的 P0，重点学习事务边界、并发、锁和 EXPLAIN ANALYZE。

必做事项：

- 补齐 P0 HTTP、真实 PostgreSQL、Web E2E 用例：越权、金额/日期边界、空态、失败重试和分页。
- 使用同一 QueryRunner/EntityManager 写入流水与幂等记录，并验证事务失败回滚。
- 验证 20 个并发相同幂等请求只新增一笔；覆盖分类归档与新建流水的竞态。
- 生成虚构数据并使用 EXPLAIN ANALYZE 检查月报索引和查询计划。

退出门槛：完整 P0 流程可在手机与桌面演示；测试证明数据隔离、幂等、金额和月报正确；有 SQL 查询计划记录。

### M5｜交付、可观测性与恢复

2027-02-01 ～ 2027-02-28

学习重点：学习 CI、请求 ID、结构化日志、数据库连接池、备份恢复和同源 HTTPS Cookie 配置。

必做事项：

- 建立 CI：安装、类型检查、API/Web 测试、构建和显式 migration 检查。
- 补充脱敏日志和统一错误结构；能够沿 requestId 定位一次失败请求。
- 完成一次虚构数据库备份/恢复与月报抽样核对。
- 完成可复现预览环境或同等部署演练；不因部署困难绕过 HTTPS、Cookie 或密钥隔离。

退出门槛：干净环境可 migration、seed、测试、启动；CI 有成功记录；备份恢复有操作记录和对账结果；本机同源 HTTPS 演练完成。公网预览缺条件时可按 §七.2 先暂停，不阻塞 M6，但公网预览未验收前不开放预览 AI。

### M6｜受限只读 AI 核心

2027-03-01 ～ 2027-03-28

学习重点：学习 ModelAdapter、结构化输出、Zod 校验、超时、预算和提示注入防护。

必做事项：

- 实现 AiModule：模型只输出有限工具计划，服务端白名单执行月报、分类汇总和最近流水等只读工具。
- 模型不得传 userId、任意 SQL、URL 或写操作；身份只能来自会话。
- 模型只输出查询计划，看不到工具查询结果；事实卡片、金额结论和回答文字都由服务端按模板生成；记录费用/耗时/错误元数据。
- 实现最小 AI 页面：加载、拒绝、超时和上游 503 状态。

退出门槛：畸形计划、恶意分类名称、越权和上游失败均安全失败；普通账本功能不受模型故障影响。

### M7｜真实评测、收口与可展示交付

2027-03-29 ～ 2027-04-25

学习重点：停止增加框架，用评测、文档和演示证明项目可靠且可解释。

必做事项：

- 建立至少 30 条虚构账本 AI 真实评测：数值与跨月、无数据或歧义、越权与写请求、注入；超时和供应商故障另做离线故障测试，不计入这 30 条。
- 记录通过率、错误分类、p95 延迟、单次与总成本；修复高优先级问题。
- 整理启动说明、架构图、迁移/种子/恢复说明、演示脚本与关键取舍。
- 从未来 iOS 客户端角度审查 API 契约：金额、分页、错误码与认证边界；不启动 iOS 客户端实现。
- 让第三方按文档从零启动并完成一次验收；AI 部分用离线 ModelAdapter，不向第三方提供模型密钥。

退出门槛：有可复现的 AI 评测报告、演示记录和从零启动证据；所有已完成能力都有对应验证。

## 六、算法并行安排

| 阶段 | 主题 | 完成标准 |
|---|---|---|
| M1 | 数组、哈希表、Big-O | 能说明输入边界、时间/空间复杂度。 |
| M2 | 双指针、滑动窗口、栈/队列 | 能独立写出基础模板并解释窗口变化。 |
| M3 | 排序、二分、前缀和 | 能分析分页、范围查询和边界条件。 |
| M4 | 树、图的 DFS/BFS | 能解释递归/迭代的选择和访问标记。 |
| M5 | 堆、优先队列、Top-K | 能解决小规模任务调度或 Top-K 问题。 |
| M6 | 基础动态规划 | 能定义状态、转移和初始条件。 |
| M7 | 错题复盘 | 整理 12～20 道真正能完整讲清的题。 |

## 七、范围与延期规则

1. 月末退出门槛未通过时，不并行启动下一个学习月；先完成当前主题的验证证据。
2. 工作或通勤导致容量下降时，先暂停算法、图表、视觉优化和公开预览；再顺延 AI。
3. 无论何时都不删减：对象权限、数据库约束、金额精度、真实 PostgreSQL 测试、幂等、密码/会话安全和休息。
4. Redis、队列、RAG、MCP、多 Agent、微服务、Kubernetes 和 iOS 客户端不在本期范围内；只有明确需求或性能证据出现时才单独立项。
5. 每个月只有一个主主题；新想法写入待评估列表，不插入当周任务。

## 八、启动周末与前两周

2026-10-09 ～ 2026-10-11：只做准备，不开始大功能。

- 在日历固定两个周末深度块和一个工作日 20 分钟复盘块。
- 运行现有检查和数据库 smoke，记录一次真实耗时；环境异常时先修复环境。
- 把 M1 拆为不超过两小时的任务卡：migration 设计、migration 命令、User Entity、Repository 测试、seed、登录、me、退出。
- 建立学习日志：日期、实际投入、完成证据、阻塞点、下个深度块唯一任务。

第 1 周（10-12 ～ 10-18）完成 schema 决策、migration 方案和第一个失败的数据库测试；第 2 周完成 migration/seed 与 User Repository。认证尚未具备测试和数据基础时，不提前做前端页面。

## 九、每月维护方式

每个学习月结束时，只记录实际完成日期、实际投入时间、退出门槛证据、未完成原因和下一月范围调整。计划的日期可顺延，质量门槛不降低。
