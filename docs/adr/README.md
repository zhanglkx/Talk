# 架构决策记录（ADR）

ADR 用一页纸记下一个重要的技术选择：当时的背景、考虑过哪些方案、最后选了什么、带来什么后果。几个月后或面试时被问"为什么这么做"，答案就在这里。

## 什么时候写

- 在两个以上合理方案之间做了选择，而且以后改起来成本不低。
- 每周至少一篇，题目写在当周迭代文档里；由作者写，助手评审。

## 命名

`docs/adr/NNNN-标题.md`，编号从 0001 递增，例如 `0001-报销类型停用而不删除.md`。被新决定取代时，旧文件不删，状态改为"已被 NNNN 取代"。

## 模板

```markdown
# NNNN 标题

- 日期：YYYY-MM-DD
- 状态：已采纳

## 背景

要解决什么问题？有哪些约束？

## 方案

- 方案 A：做法、优点、缺点
- 方案 B：做法、优点、缺点

## 决定

选了哪个，主要理由。

## 后果

带来的好处和代价；以后出现什么情况需要重新考虑。
```
