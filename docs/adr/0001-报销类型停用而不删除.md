# 0001 报销类型停用而不删除

- 日期：2026-11-19
- 状态：已采纳

## 背景

报销类型由管理员维护。员工填写明细时从中选择，财务按类型汇总。业务上需要把过时类型从新明细的选项中移除，同时让已有单据继续通过类型 ID 查到名称。 [PRD 第 4 节](../PRD.md#4-业务规则)

## 方案

- **物理删除类型。** 管理员可以清理未使用的记录。类型被明细引用后，外键会阻止删除，管理员仍需要一种方式把它从新明细的选项中移除。
- **用 `deleted_at` 软删除。** 可以保留记录和删除时间。日常查询要过滤已删除记录，历史查询要能读到归档记录，还需要约定同名创建和恢复冲突时怎么处理。
- **用 `enabled` 标记是否启用。** 类型保留原 ID，管理员可以反复启停。新明细、管理列表和历史单据各有明确的查询条件。

## 决定

我采用 `enabled` 布尔字段。新建默认启用，`enable` 和 `disable` 接口把 `enabled` 改为目标值，管理列表仍可查看两种状态。数据库的 `uq_expense_types_name` 唯一约束覆盖所有记录，停用的类型仍占用原名称，需要时可以直接重新启用。 [W01 报销类型设计](../plan/W01-从零跑通.md)

W02 的明细通过外键引用类型 ID。新增明细只从已启用类型中选择，保存时由 API 检查启用状态。提交或重新提交时，API 再确认单据里的类型都已启用。历史单据按 ID 查类型时会包含已停用记录，并显示当前名称。

## 后果

- 历史单据仍可参与按类型的汇总，停用的字典记录及其索引也会继续占用空间。
- 测试需要验证新明细会拒绝停用类型，历史记录仍可读取，类型可以重新启用，停用期间原名称仍不能重用。
- 如果将来需要在历史单据上显示填报当时的名称，再决定是否在明细中保留类型名称快照。
