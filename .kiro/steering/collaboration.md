# 分工、验证与证据

## 分工

依据 M1 README「当前步骤」的执行分工；阶段 README 或用户在对话里另有指定时，以其为准。

- 业务代码由用户手写，即 `apps/api/src/`、`apps/web/src/` 下的实现（`src/generated/` 除外）。助手不改、不代写，也不为验证测试而临时改动业务实现。
- 助手负责：按当前步骤的「动作」写测试、运行验证、在阶段 README 里维护证据。写测试是用户对本项目的明确要求，但只写当前步骤需要的；除非该步写明，不新增测试依赖、测试配置或 npm 脚本。
- 测试先于用户的实现写好并运行，确认按预期失败。用户实现后仍失败时，报告失败的断言、原因和文件位置，由用户修改。
- 脚本、配置等其他文件的改动按当前步骤写明的分工；没写明就先问用户。

## 证据

- 记录日期、命令、结果（文件数、测试数）、测试文件位置，以及没有验证到的部分。
- 证据里只写测试库名，不写连接串、密码或账号。

## 环境

- 不修改 `.env`，不回显其中的值；不关闭用户的 PostgreSQL；测试不用真实账号或连接串。
- 需要「数据库不可达」时，只给单条命令注入虚构地址，并先确认它确实连不上（例如得到 `ECONNREFUSED`）。
- 真实数据库测试只连专用测试库，库名记在阶段 README。
